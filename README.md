# Backend — سامانه مدیریت مدرسه

[تحلیل جامع سامانه مدیریت مدرسه](../SCHOOL_MANAGEMENT_SYSTEM_ANALYSIS.md).

```bash
python -m venv .venv
```

```bash
.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

```bash
cd backend && cp .env.example .env
```

```bash
cd backend && python manage.py migrate
```

```bash
cd backend && python manage.py seed_demo
```

```bash
cd backend && python manage.py runserver
```

## معماری

هر اپ Django معادل یک **Bounded Context** از بخش ۶.۱ سند تحلیل است:

| اپ | Bounded Context | موجودیت |
|---|---|---:|
| `core` | زیرساخت مشترک (Tenant، خطا، مجوز، صفحه‌بندی) | ۱ |
| `identity` | Identity & Access | ۱۳ |
| `organization` | Organization & Academic Setup | ۱۳ |
| `students` | Admissions & Student Records | ۱۱ |
| `hr` | HR & Workforce | ۱۴ |
| `teaching` | Teaching & Learning | ۹ |
| `assessment` | Assessment | ۱۶ |
| `gradebook` | Gradebook | ۷ |
| `finance` | Billing & Accounting | ۱۶ |
| `inventory` | Procurement & Inventory | ۱۷ |
| `welfare` | Student Welfare & Auxiliary Services | ۱۶ |
| `workflow` | Communication & Workflow | ۱۲ |

**جمع: ۱۴۵ موجودیت، ۴۲۶ مسیر، ۹۰۹ عملیات API.**

### ساختار هر اپ

```
apps/<context>/
├── models.py       موجودیت‌ها + قیدهای پایگاه داده
├── enums.py        وضعیت‌ها و انواع با برچسب فارسی
├── serializers.py  قرارداد ورودی/خروجی + اعتبارسنجی فیلدی
├── services.py     قواعد کسب‌وکار و ماشین‌های حالت
├── views.py        ViewSetها + Endpointهای تغییر وضعیت
├── filters.py      فیلترهای پیچیده (در صورت نیاز)
├── urls.py         Router
└── admin.py        پنل مدیریت
```

قواعد کسب‌وکار در `services.py` است، نه در View — تا از هر مسیری (API، دستور
مدیریتی، Job) قابل فراخوانی باشد.

### مستندسازی خودکار قرارداد

| فایل | نقش |
|---|---|
| `apps/core/schema.py` | `PersianAutoSchema` (عنوان و توضیح فارسی اکشن‌های استاندارد) + Hook پس‌پردازش (نمونه، برچسب فیلد، پاسخ‌های خطا) |
| `apps/core/schema_labels.py` | واژه‌نامه فارسی نام فیلدها، برای فیلدهایی که `verbose_name` ندارند |

هر `@extend_schema` صریح روی متن تولیدشده مقدم است؛ این دو فایل فقط جای خالی را
پر می‌کنند، پس منبع تازه بدون هیچ کار اضافه، مستند وارد Swagger می‌شود.

## اصول پیاده‌سازی‌شده از سند تحلیل

### شناسه و تاریخچه (بخش ۵.۱)

- کلید اصلی همه موجودیت‌ها **UUID**
- `created_at` / `created_by_id` / `updated_at` / `updated_by_id` / `version`
- `version` برای **کنترل هم‌زمانی خوش‌بینانه** (هدر `If-Match` + `ETag`)
- حذف عملیاتی = **حذف نرم** (`deleted_at` + علت)
- اسناد مالی و انبار قطعی: `ImmutableLedgerModel` — بدون حذف، اصلاح فقط با سند معکوس
- انتساب‌های زمان‌مند: `effective_from` / `effective_to`

### دسترسی (بخش ۳.۲ و ۱۵.۱)

- **RBAC + Scope**: ۲۰۹ مجوز اتمی، ۱۷ نقش سیستمی، ۷ نوع Scope
- فیلتر Tenant/Scope در **لایه Queryset** اعمال می‌شود و با پارامتر Query دور نمی‌خورد
- کنترل شیء برای قاعده `SELF` (دانش‌آموز/ولی)
- **تفکیک وظایف**: ایجادکننده ≠ تأییدکننده در استرداد، خرید و مرخصی
- ممیزی Append-only با ماسک‌کردن مقادیر راز

### مالی (بخش ۷.۸)

- مبالغ **عدد صحیح به ریال** — بدون اعشار شناور
- حسابداری دوبل با قید پایگاه داده: هر خط یا بدهکار است یا بستانکار
- سند قطعی تغییرناپذیر؛ اصلاح فقط با سند برگشتی
- کنترل توازن پیش از قطعی‌سازی
- حساب گروه اجازه ثبت مستقیم ندارد
- دوره مالی بسته → `PERIOD_CLOSED`
- پیش‌دریافت: دریافت تا پیش از تخصیص، بدهی است؛ پس از تخصیص به دریافتنی منتقل می‌شود

### آزمون (بخش ۷.۶)

- آزمون به **نسخه ثابت سؤال** ارجاع می‌دهد؛ ویرایش سؤال، آزمون گذشته را تغییر نمی‌دهد
- شروع تلاش **Idempotent**؛ قطع اتصال → ادامه همان تلاش
- کلید پاسخ هرگز در برگه آزمون دانش‌آموز برنمی‌گردد
- رخداد مراقبت فقط «شاهد» است؛ تصمیم تخلف با انسان
- تحویل نهایی اتمیک و تکرارپذیر

### انبار (بخش ۷.۹)

- موجودی فقط از `StockMovement` قطعی تغییر می‌کند
- موجودی قابل‌دسترس = `on_hand − reserved`
- کالای سریال‌دار/بچ‌دار در خروج نیازمند شناسه
- تطبیق سه‌طرفه سفارش/رسید/فاکتور با تلورانس قابل تنظیم

## پنل مدیریت

پنل روی `‎/admin/‎` کاملاً فارسی و راست‌به‌چپ است. جهت صفحه و بارگذاری
`rtl.css` را خودِ جنگو از `LANGUAGE_CODE = "fa"` نتیجه می‌گیرد؛ بقیه موارد
پیکربندی این پروژه است.

### پوشش موجودیت‌ها

هر ۱۴۵ موجودیت ثبت شده‌اند. `ModelAdmin` دست‌نویس برای موجودیت‌های پرکاربرد
نوشته شده و بقیه از `register_auto` در `apps/core/admin.py` پیکربندی می‌گیرند:
ستون فهرست، فیلتر، فیلد جست‌وجو و نوع ویجت کلید خارجی از روی خودِ مدل مشتق
می‌شود.

```python
# انتهای apps/<context>/admin.py
register_auto(*apps.get_app_config("<label>").get_models())
```

مدلی که `ModelAdmin` دست‌نویس دارد نادیده گرفته می‌شود، پس افزودن مدل تازه
بدون هیچ کار اضافه‌ای در پنل ظاهر می‌شود.

| رفتار | قاعده |
|---|---|
| ستون فهرست | معرّف رکورد ← مالک ← وضعیت ← تاریخ ← زمان ایجاد (حداکثر ۷) |
| فیلتر | فقط فیلدهای `choices` و بولی — کلید خارجی عمداً نه |
| کلید خارجی | `autocomplete` اگر مدل مقصد فیلد جست‌وجو دارد، وگرنه `raw_id` |
| فیلدهای ممیزی | فقط‌خواندنی، در بخش جمع‌شونده «اطلاعات ممیزی» |
| حذف نرم | فیلتر «وضعیت حذف» + اکشن بازگردانی |
| سند قطعی | `ImmutableLedgerModel` → بدون افزودن، ویرایش و حذف |

### ترتیب ماژول‌ها و موجودیت‌ها

جنگو صفحه اصلی را الفبایی مرتب می‌کند؛ نتیجه‌اش این است که «اقلام فیش» بالاتر
از «پرسنل» می‌نشیند. `apps/core/admin_site.py` ترتیب را بر اساس اولویت استفاده
بازتعریف می‌کند:

| # | ماژول | # | ماژول |
|---|---|---|---|
| ۱ | منابع انسانی | ۷ | بانک سؤال و آزمون |
| ۲ | هویت و دسترسی | ۸ | مالی و حسابداری |
| ۳ | ساختار سازمانی و آموزشی | ۹ | خدمات دانش‌آموزی |
| ۴ | پذیرش و امور دانش‌آموزان | ۱۰ | خرید، انبار و اموال |
| ۵ | آموزش، حضور و تکلیف | ۱۱ | گردش کار و ارتباطات |
| ۶ | دفتر نمره و کارنامه | ۱۲ | زیرساخت مشترک |

درون هر ماژول هم موجودیت اصلی اول می‌آید و جدول‌های سطر/قلم و لاگ آخر — مثلاً
در منابع انسانی: پرسنل ← پرونده معلم ← انتساب تدریس ← … ← اقلام فیش.

برای تغییر ترتیب فقط `APP_ORDER` و `MODEL_ORDER` را در همان فایل جابه‌جا کنید.
هرچه در فهرست نیامده باشد پس از موارد فهرست‌شده و الفبایی می‌آید، پس افزودن
مدل تازه چیزی را نمی‌شکند. نوار کناری از همین ترتیب تغذیه می‌شود.

پنل از `AdminSite` سفارشی استفاده می‌کند که با
`apps.core.admin_apps.SchoolAdminConfig` در `INSTALLED_APPS` جای
`django.contrib.admin` نشسته است — روش مستند خود جنگو، پس `admin.register` و
مسیرهای `/admin/` بدون تغییر کار می‌کنند.

### برچسب فارسی فیلدها

از ۲۵۹۳ فیلد سامانه، ۱۰۴۴ فیلد `verbose_name` صریح نداشتند و جنگو نام انگلیسی
فیلد را نشان می‌داد. واژه‌نامه `apps/core/field_labels.py` این جای خالی را
پر می‌کند و `CoreConfig.ready()` آن را پیش از ساخته‌شدن اولین فرم اعمال می‌کند.

یک واژه‌نامه، سه مصرف‌کننده: سرستون و فرم پنل مدیریت، `label` سریالایزرهای
DRF، و `title` مشخصه‌ها در قرارداد OpenAPI. فیلدی که در `models.py` برچسب
فارسی دارد دست نمی‌خورد.

### پوسته و فونت

فونت **وزیرمتن** (مجوز SIL OFL) در `static/school_admin/fonts/` میزبانی محلی
شده تا پنل بدون دسترسی به اینترنت هم درست نمایش داده شود. پوسته نارنجی در
`static/school_admin/css/admin-theme.css` فقط متغیرهای CSS خود جنگو را
بازتعریف می‌کند و هر سه حالت روشن، تیره و «مطابق سیستم» را پوشش می‌دهد.

نسبت کنتراست متن سفید روی رنگ‌های اصلی پوسته ۴٫۵۸ تا ۹٫۳۵ است — بالاتر از حد
WCAG AA برای متن معمولی.

## پایگاه داده

پیش‌فرض **SQLite** در `backend/database/db.sqlite3` است. برای PostgreSQL کافی
است `DATABASE_URL` را در `.env` پر کنید؛ بقیه تنظیمات خودکار عوض می‌شود:

```
DATABASE_URL=postgres://user:pass@localhost:5432/school
```

## ساختار پوشه‌ها

```
backend/
├── apps/          کد ماژول‌ها
├── config/        تنظیمات و مسیرها
├── assets/        فایل ثابتِ منبع (پوسته و فونت پنل) — داخل مخزن
├── database/      فایل SQLite — بیرون از مخزن
├── public/        تنها پوشه‌ای که به وب‌سرور معرفی می‌شود
│   ├── static/    خروجی collectstatic
│   └── media/     فایل‌های آپلودی
└── docs/          قرارداد OpenAPI و راهنمای فرانت
```

`database/` و `public/` هر دو در `.gitignore` هستند و هنگام اجرا خودکار ساخته
می‌شوند. `assets/` منبع است و باید در مخزن بماند.

چون پایگاه داده و کد بیرون از `public/` هستند، پیکربندی اشتباه وب‌سرور هم
نمی‌تواند آن‌ها را افشا کند. با `DEBUG=False` فایل‌های ثابت از `public/static/` خوانده می‌شوند، پس
`collectstatic` یک مرحله **اجباری** استقرار است:

```bash
cd backend && python manage.py collectstatic --noinput
```

`whitenoise` در میان‌افزار هست، یعنی اگر وب‌سرور مسیر `/static/` را تنظیم نکرده
باشد خود Django جواب می‌دهد و پنل و Swagger سالم می‌مانند. با این حال سپردن
`/static/` به وب‌سرور سریع‌تر است — در nginx فقط دو مسیر زیر را بدهید:

```
location /static/ { alias /srv/school/backend/public/static/; }
location /media/  { alias /srv/school/backend/public/media/;  }
```

## تنظیمات محیط

فایل `.env.example` را به `.env` کپی کنید. همه گزینه‌ها آنجا با توضیح فارسی
فهرست شده‌اند؛ مهم‌ترین‌ها:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `DJANGO_SECRET_KEY` | کلید توسعه | **در عملیات حتماً تغییر دهید** |
| `DJANGO_DEBUG` | `True` | در عملیات `False` |
| `DJANGO_ALLOWED_HOSTS` | `localhost,127.0.0.1` | دامنه‌های مجاز، بدون پروتکل |
| `CSRF_TRUSTED_ORIGINS` | — | مبدأ پنل پشت HTTPS، **با** پروتکل |
| `CORS_ALLOWED_ORIGINS` | `localhost:3000,5173` | مبدأهای فرانت، با پروتکل و پورت |
| `CORS_ALLOW_CREDENTIALS` | `False` | اگر فرانت با کوکی کار می‌کند `True` |
| `ADMIN_URL` | `admin/` | تغییرش پنل را از دید اسکنرها خارج می‌کند |
| `DATABASE_URL` | — | خالی = SQLite در `database/` |
| `DATABASE_DIR` / `PUBLIC_DIR` | کنار پروژه | برای جابه‌جایی به مسیر مطلق |
| `USE_X_FORWARDED_PROTO` | `False` | پشت nginx/traefik حتماً `True` |
| `LOG_LEVEL` | `INFO` | `DEBUG` تا `ERROR` |
| `SCHEMA_CACHE_SECONDS` | `900` | کش قرارداد OpenAPI؛ صفر = خاموش |
| `API_SERVERS` | خالی | سرورهای قرارداد؛ خالی = هم‌مبدأ با صفحه مستندات |
| `JWT_ACCESS_MINUTES` | `30` | عمر توکن دسترسی |
| `JWT_REFRESH_DAYS` | `7` | عمر توکن تازه‌سازی |

با `DJANGO_DEBUG=False` این موارد خودکار روشن می‌شوند: HSTS، ریدایرکت HTTPS،
کوکی امن، `X-Frame-Options: DENY`. همه‌شان در `.env` قابل بازنویسی‌اند —
پشت Reverse Proxy که خودش TLS را تمام می‌کند، `SECURE_SSL_REDIRECT` بدون
`USE_X_FORWARDED_PROTO=True` حلقه ریدایرکت می‌سازد.

پیش از استقرار:

```bash
cd backend && python manage.py check --deploy
```

## کارهای باقی‌مانده برای محیط عملیاتی

این موارد عمداً به‌صورت نقطه اتصال (Adapter) رها شده‌اند و پیاده‌سازی آنها به
محیط استقرار بستگی دارد:

| مورد | وضعیت فعلی | لازم برای عملیات |
|---|---|---|
| شماره‌گذاری اسناد | شمارش رکورد | Sequence اتمیک پایگاه داده (بار همزمان) |
| انتشار Outbox | ثبت در جدول | Worker (Celery/RQ) برای انتشار به صف |
| ارسال اعلان | صف‌گذاری در DB | اتصال به Provider پیامک/ایمیل/Push |
| درگاه پرداخت | ثبت `gateway_reference` | Callback امضاشده درگاه واقعی |
| اسکن بدافزار فایل | فیلد `scan_status` | اتصال به سرویس آنتی‌ویروس |
| MFA | فیلد `mfa_enabled` | پیاده‌سازی TOTP/SMS |
| تحویل خودکار آزمون | تابع آماده | زمان‌بند دوره‌ای (Cron/Celery Beat) |
| قواعد حقوق و دستمزد | فیش پایه | افزونه محلی مطابق قوانین کشور |
| Object Storage | `FileField` محلی | S3/MinIO با URL امضاشده |

## کیفیت قرارداد API

```bash
cd backend && python manage.py spectacular --file docs/openapi.yaml
```

خروجی فعلی: **۰ خطا، ۰ هشدار** — ۴۲۶ مسیر، ۹۰۹ عملیات، ۷۷۱ Schema.

پوشش مستندات:

| سنجه | وضعیت |
|---|---|
| عملیات دارای عنوان فارسی | ۹۰۹ از ۹۰۹ |
| عملیات دارای توضیح فارسی | ۹۰۹ از ۹۰۹ |
| فیلدهای دارای برچسب یا توضیح فارسی | ۵۱۱۶ از ۵۱۱۶ |
| Schemaهای شیء دارای نمونه | ۶۲۶ از ۶۲۶ |
| عملیات دارای پاسخ‌های خطای استاندارد | ۹۰۹ از ۹۰۹ |

نام Enumها با `ENUM_NAME_OVERRIDES` تثبیت شده‌اند تا تولید مجدد تایپ TypeScript
باعث تغییر نام تایپ‌ها نشود.
